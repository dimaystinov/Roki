# FPV Roki — автономные приложения

## macOS

Сборка `dist/FPV Roki.app` содержит Python, Qt, KDDockWidgets и GStreamer.
На компьютере пользователя не нужны Homebrew, Python, папка исходного проекта
или виртуальное окружение. Скопируйте приложение в «Программы».

Текущая локальная сборка: **arm64 (Apple Silicon), macOS 26.0+**. Ограничение
определено по LC_BUILD_VERSION всех включённых Mach-O, а не по версии оболочки.
Для Intel и старых macOS эту сборку использовать нельзя: нужна отдельная сборка
с совместимыми зависимостями. Подпись ad-hoc; Apple Developer signing и
notarization не выполнены. Загруженный с другого компьютера пакет может
потребовать стандартного подтверждения открытия в настройках macOS.

Приложение стартует без подключения, передачи видео и команд движения.
Адрес по умолчанию — 192.168.0.244. После подключения получите управление,
выберите MANUAL, запустите камеру и в «Стримах» выберите `camera` → «Смотреть».

### Воспроизведение на машине сборки

1. Подготовить зависимости по `docs/MACOS.md`.
2. Установить PyInstaller 6.22.3 в `.deps/macos/venv`.
3. Выполнить `packaging/build_macos.sh`.
4. Выполнить `packaging/audit_macos.py` через Python сборочного окружения,
   передав путь к `.app`. Проверка отклоняет внешние non-system зависимости.
5. Запустить исполняемый файл внутри `.app` с `--self-test-gui` и
   `--self-test-video`. Второй тест передаёт локальные RTP/H.264 и проверяет
   QImage; робот не используется.

Все Qt библиотеки и плагины берутся из той же сборки, что и KDDockWidgets:
смешивать Homebrew Qt и Qt из wheel нельзя даже при одинаковом номере версии.

## Windows x64 — автономный ZIP

Windows-пакет собирается на Windows x64, не на macOS. Конфигурация находится
в `packaging/windows-environment.yml`, сборка — `packaging/build_windows.ps1`.
Нужны Visual Studio C++ build tools и активированное указанное conda-окружение
**только на машине сборки**. Нативный bootstrap экспортирует C-интерфейс DLL.

В объединённом репозитории сборку выполняет `.github/workflows/fpv-release.yml`.
Исходники передаются через Linux job: в архивной части общего репозитория есть
имена файлов сайта с `?`, которые Git для Windows не может извлечь.
Windows job собирает зависимости, запускает unit-тесты, проверяет GUI и локальный
H.264, затем сохраняет ZIP и прикладывает его к черновику релиза.
Страница загрузки: https://github.com/dimaystinov/Roki2_Full/releases.

В результате сборки ZIP содержит `FPV Roki/FPV Roki.exe`, библиотеки и
`Install-FPV-Roki.ps1`. Можно запускать exe прямо из распакованного каталога
или установить для текущего пользователя: скрипт копирует файлы в
`%LOCALAPPDATA%/Programs/FPV Roki` и создаёт ярлык в меню «Пуск».
Python, conda и исходный проект конечному пользователю не нужны.

Пакет не подписан сертификатом Windows Authenticode. Для установки сначала
полностью распакуйте ZIP; не запускайте exe непосредственно внутри архива.
Скрипт установки необязателен: приложение работает и из распакованной папки.

### Особенности проверки Windows

Тестовый UDP-сервер обрабатывает `ConnectionResetError`: Windows возвращает
такую ошибку при ICMP-ответе на пакет уже закрытого клиента. Поток тестового
сервера должен продолжить приём следующего подключения.

Готовый exe проверяется с `PATH`, содержащим только Windows/System32 и Windows,
чтобы библиотеки среды сборки не скрывали отсутствующие зависимости поставки.
Windows-приложение использует программный рендеринг Qt Quick и стиль Fusion
по умолчанию. Для Qt 6.7.3 включён `QV4_FORCE_INTERPRETER=1` и отключён дисковый
QML-кэш: без этого полный Operator.qml воспроизводимо завершается с access
violation, а в указанном режиме полный GUI проходит проверку. Это ограничение
текущей Windows-поставки; JIT и аппаратный рендеринг не заявлены проверенными.
Интерпретатор касается JavaScript-привязок интерфейса, а не UDP-протокола или
декодера H.264. Диагностика автономных тестов
пишется в `fpv-self-test.log`, включая Qt-сообщения и нативные Python-стеки.
