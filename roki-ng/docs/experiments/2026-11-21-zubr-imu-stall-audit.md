## Подтверждённые дефекты обработки отказов

1. `HwImu.cpp`, периодическая задача в конце `HwImu::init`:
   результаты `bhy2_get_interrupt_status` и `bhy2_get_and_process_fifo`
   отбрасываются. `mError` отражает инициализацию, а не ошибки работающего IMU.
2. Обе SPI callback-функции возвращают `IMU_ERR_OK` без проверки результата
   передачи. `SvSpiDevice::spiRead/spiWrite` имеют тип `void`.
3. `SvSpiDevice.cpp`: ожидания `smWait` для TXC/DMA не имеют срока окончания;
   также есть busy-wait TXP/RXP. Кооперативное ожидание может остановить
   только задачу IMU, оставив остальные задачи контроллера живыми. Busy-wait
   без yield имеет другой, более широкий эффект, поэтому его нельзя считать
   доказанной причиной наблюдаемого частичного зависания.
4. Нет watchdog по времени последнего нового измерения, обработки
   `BHY2_IS_INT_RESET` или восстановления состояния BHI после сбоя.
   Инициализация выполняется один раз из `HwMainLoop.cpp`.
5. Kondo RAM-reader возвращает сохранённые mIntX/Y/Z/W и ACC/GYRO без признака
   возраста. Успешный ответ UART не означает новое измерение.

В библиотеке уже определены reset-fault bit 0x80 и meta events SENSOR_ERROR,
FIFO_OVERFLOW, INITIALIZED, RESET. Прикладной код не использует их для
диагностики и восстановления. Статусный FIFO отключён в настройках init.

## Что это объясняет — и чего не доказывает

Отсутствие восстановления объясняет, почему кратковременный сбой превращается
в постоянные старые данные до полного отключения питания. Если BHI сбросится,
RAM-загруженная программа и конфигурация датчиков требуют восстановления;
одного продолжения чтения FIFO недостаточно.

Но физический первичный триггер падения не установлен: возможны локальная
просадка питания BHI, контакт/помеха, сбой его firmware/FIFO или зависшая
транзакция STM32. По нынешнему интерфейсу эти состояния не различимы.
Обновляющийся ADC не исключает локальной просадки питания самого IMU.

## Необходимое исправление и проверка

- Сначала подтвердить ревизию Zubr и соответствие исходников установленной
  сборке. Не использовать прошивальщик платы головы для платы тела.
- Ограничить ВСЕ SPI/DMA ожидания, возвращать ошибки вверх, снимать CS и
  приводить SPI/DMA в согласованное состояние после аварии.
- Записывать фазу задачи, код ошибки SPI/Bosch, interrupt/boot/error status,
  счётчики ошибок, перезапусков и время последнего измерения.
- Ввести watchdog по новым timestamps/счётчику измерений, а не по изменению
  углов. При reset/fault/потере прогресса инвалидировать измерения.
- Выполнять ограниченное восстановление BHI в одной существующей задаче:
  reset → загрузка RAM firmware → конфигурация → ожидание новых измерений.
  Нельзя просто повторно вызвать нынешний init(): он создаёт ещё одну задачу.
- Не перезапускать всё тело и не возобновлять моторное задание автоматически.
  После восстановления сообщать новый epoch ориентации: yaw может сброситься.
- Проверить с искусственными ошибками SPI, остановкой timestamp, reset BHI,
  восстановлением FIFO, затем на стенде без ходьбы. Осциллографом проверить
  питание непосредственно на IMU при нагрузке/механическом воздействии.

Ранее подготовленный `imu-counter.patch` только обнаруживает остановку
измерений. Он НЕ содержит такого восстановления; выдавать его за исправление
зависания нельзя.
